# Grants — правила разработки

## Продукт

SvelteKit + TypeScript + SCSS. Лендинг «Искра» по вкладке **«Гранты»** Figma. Не использовать контент WagonBid. Анимации пока не добавлять.

## Роли

- `.github/agents/developer.agent.md` — разработчик: компоненты, адаптивность, доступность, стили.
- `.github/agents/playwright-tester.agent.md` — QA: Playwright, сравнение с Figma, интерактивность и overflow.

## Структура

Импорты внутри проекта — только через алиас `@` (указывает на `src/`), настроен в `vite.config.ts`, `svelte.config.js` и `tsconfig.json`.

Каждый компонент — в собственной папке: `ИмяКомпонента/ИмяКомпонента.svelte` + `ИмяКомпонента.scss` (подключается через `@use './ИмяКомпонента.scss';` в блоке `<style lang="scss">`, scoping Svelte сохраняется) + при необходимости `constants.ts` с данными, которые шаблон прогоняет через `{#each}`. Стили — по БЭМ; селекторы по тегам (`a`, `div`, `h2` и т.п.) запрещены — у каждого элемента свой класс.

- `src/presentation/components/ui` — переиспользуемые элементы.
- `src/presentation/components/sections` — самостоятельные блоки лендинга.
- `src/presentation/layout` — Header и Footer.
- `src/presentation/styles` — токены, миксины, шрифты и глобальные стили.
- `tests` — Playwright-проверки.

## Обязательные требования

1. Цвета, отступы, радиусы и брейкпоинты выносить в переменные; повторяющиеся паттерны — в миксины или компоненты.
2. Не задавать странице или секциям фиксированную высоту ради совпадения скриншота. Высота должна следовать из контента и отступов.
3. Проверять 320, 375, 768, 1024, 1440 и 1920 px; горизонтальный overflow недопустим.
4. Работу вести отдельными блоками и брейкпоинтами. Эталонные изображения Figma не перезаписывать скриншотами реализации.
5. Перед завершением: `npm run check`, `npm run build`, `npm test`.
6. Не коммитить и не публиковать без явного подтверждения пользователя после его проверки.
7. Временные файлы, старые эталоны, неиспользуемые изображения и вспомогательные скрипты удалять сразу после использования.
